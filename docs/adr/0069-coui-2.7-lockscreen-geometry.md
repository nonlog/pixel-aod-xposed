# ADR 0069: COUI 2.7 lockscreen geometry compatibility

## Context

The persistent Pixel clock host was originally ported from COUI Expressive 2.5. On the current
CPH2573/OOS 16.0.9-class lockscreen, compact times containing corrected digits such as `0` or `1`
can move the complete clock horizontally relative to the native notification card. COUI Expressive
2.7 also changed its design-unit conversion so lockscreen geometry follows the measured display
width rather than the current Android density override alone.

The installed COUI Expressive 2.7.260912 APK was pulled from the physical device and inspected as
local-only reference material. Reference source and APK files are not production dependencies and
must remain outside Git history.

## Decision

1. Compact and immersed clock centering uses the COUI 2.7 stable four-`8` reference width. The
   actual current digit widths still advance the four glyph targets, and the existing `0`/`1`
   optical corrections remain intact. This fixes the anchor; it is not a device-specific x-offset.
2. The COUI clock host converts design dp using the COUI 2.7 reference of 538 dpi at 1272 px and
   scales that reference by the measured host width. Before first measure, the display width is the
   fallback.
3. A host-width or configuration change recomputes information text sizes and the Pixel-specific
   weather, contextual, media, notification, burn-in, and spacing metrics through the same design
   coordinate system.
4. OPlus remains the owner of the notification card layout, notification swipe/snap behavior,
   media seekbar, UDFPS sensing/HBM, AOD power lifecycle, and native lockscreen policy.
5. COUI 2.7 notification batching/icon caching and UDFPS HDR/glow fixes are reviewed separately.
   They may be ported only where the current Pixel AOD implementation has the same causal issue;
   they are not bundled into the geometry change.

## Rejected alternatives

- Add a fixed 12-13 px right translation for CPH2573: it would only match one time/DPI and would
  retain the underlying digit-dependent centering bug.
- Copy COUI's notification-style rewrite wholesale: Pixel AOD does not own native notification card
  styling or scroll physics.
- Replace OPlus notification or fingerprint lifecycle ownership to obtain alignment: unnecessary
  for a clock geometry defect and contrary to the existing vendor-delegation ADRs.

## Consequences

- Compact lockscreen/AOD positions stay stable as the displayed digits change.
- Relative geometry is resilient to user DPI overrides and follows the same reference coordinate
  system as current COUI.
- Any future Pixel-specific child added to the COUI host must either use the host design metrics or
  explicitly document why it belongs to a different coordinate system.
