# ADR 0070: COUI 2.7 notification hot-path optimizations

## Context

Pixel AOD already filters notification state through its own OPlus-aware admission/ranking pipeline and
coalesces listener snapshots. COUI Expressive 2.7 adds two narrower performance mechanisms that map
to work Pixel AOD still performs: a reusable multi-delay refresh batch and a bounded notification
icon snapshot cache. COUI 2.7 also reuses a thread-local pixel array when rasterized icons are
classified.

The installed COUI Expressive 2.7.260912 APK is local-only reference material and is not a build or
runtime dependency.

## Decision

1. Keep the existing `NotificationSnapshotRefreshGate` unchanged. It remains the owner of normal
   listener snapshot coalescing.
2. Use a COUI-style `NotificationRefreshBatch` only for the existing live-alert/torch
   `40/280/900 ms` reconciliation sequence. Each delay owns at most one pending runnable, a newer
   request replaces its action, and the final delayed pass is moved to the burst's trailing edge.
3. Cache resolved notification icon snapshots in an access-ordered 64-entry cache. A hit requires
   the exact `StatusBarNotification` object, exact small `Icon` object, equivalent Android
   `Configuration`, and current Material info tint. Per-key removal invalidates immediately.
4. Store immutable raster snapshot state rather than a live app drawable so a cached result cannot
   inherit later bounds/tint mutations. Raster dimensions are bounded to 256 px per side, matching
   the COUI 2.7 upper bound.
5. Reuse a thread-local integer pixel buffer for the 48 x 48 icon classifiers. Keep all existing
   silhouette/color thresholds and restore source drawable bounds after sampling.
6. Do not alter notification eligibility, ranking precedence, native OPlus card ownership,
   lockscreen/AOD presentation rules, or the existing capsule icon bridge.

## Rejected alternatives

- Replace the existing snapshot gate with COUI's complete notification scheduling stack: the project
  already has validated OPlus-specific coalescing and lifecycle gates, so wholesale replacement
  would regress established behavior.
- Cache unbounded icon drawables: long-running SystemUI must have a hard retention limit, and live
  drawable instances may carry mutable state.
- Copy COUI's notification card styling, Monet background, or scroll/snap changes: those surfaces
  are owned by native OPlus SystemUI, not Pixel AOD.
- Bundle UDFPS 2.7 changes into the same build: fingerprint HDR/AOD lifecycle ownership needs
  separate physical validation.

## Consequences

- Bursty live-alert/torch state no longer creates three additional delayed runnables per event.
- Repeated semantic refreshes can reuse resolved icon pixels while configuration, icon identity,
  notification identity, and tint remain stable.
- Icon classification eliminates thousands of JNI-backed per-pixel reads per cache miss while
  retaining the same decision thresholds.
- The cache has deterministic bounded retention and explicit invalidation on notification removal
  or content reset.
