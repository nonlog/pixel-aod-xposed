# ADR 0071: COUI 2.7 UDFPS HDR surface-state dedupe

## Status
Accepted for the 0.1.49 candidate.

## Context
COUI Expressive 2.7 adds a new HDR press lifecycle around the vendor UDFPS pressed carrier. In addition to deduping pressed-state transitions and reapplying HDR on the next animation frame, the upstream implementation can force the vendor pressed carrier visible during non-interactive/AOD presses and call OPlus `AODDisplayUtil.requestScreenState(view, state, true)`.

The decompiled 2.7 constants name screen state `1` as OFF and `3` as DOZE. That request therefore crosses into AOD/display lifecycle control. Pixel AOD intentionally leaves AOD power state, panel policy, HBM/local-HBM, optical sensing, touch routing, and native pressed-carrier visibility under OPlus ownership unless a narrow physical defect proves an exception is necessary.

Pixel AOD already has the other important 2.7 stabilization: after HDR window layout work it re-reads live touch state on the next animation frame so a recreated `SurfaceControl` does not inherit stale idle/pressed headroom.

## Decision
Port only the visual/performance-safe transition dedupe:

- Track the last successfully applied module HDR state by pressed carrier, press-active bit, and exact `SurfaceControl` object identity held weakly.
- Skip the `SurfaceControl.Transaction` when both press state and surface identity are unchanged.
- Treat a different surface identity as requiring a fresh transaction even if the press bit is unchanged.
- Force a fresh transaction on the existing post-`updateViewLayout()` animation-frame recheck, because layout work can recreate or reset surface state.
- Record state only after a successful transaction.
- Clear module dedupe state when HDR replacement ownership is disabled or the pressed carrier is restored.

Do not port:

- `AODDisplayUtil.requestScreenState(...)` calls;
- module-requested OFF/DOZE transitions;
- AOD-only forced visibility of the vendor pressed carrier;
- any DisplayPowerController, panel, HBM, local-HBM, sensing, or touch-routing ownership.

## Consequences
Repeated UiMech/async refresh bursts during one fingerprint press no longer emit redundant HDR `SurfaceControl` transactions on the same surface. Surface recreation and explicit HDR window layout remain repair points rather than being hidden by the dedupe gate.

If a future CPH2573 trace proves that the vendor pressed carrier is genuinely hidden or the panel state is insufficient during an HDR AOD press, that defect must be investigated separately before any visibility or screen-state request is considered.
